# AI 辅助分析 · 规则

## 判断原则

1. **不臆测**：只基于提供的 data 事实判断，不猜测未提供的信息。如果信息不足，在 reason 里说明。
2. **给理由**：每条判断（accuracy / canIgnore）都要在 reason 字段说明依据。理由要具体，不要泛泛而谈。
3. **标可忽略**：明确哪些分析结果可以忽略。典型场景：
   - 轻量项目（小游戏 / 工具类，files < 20）本就不需要全套文档，阶段进度低不代表有问题
   - 该产物对当前项目类型无意义（如纯后端项目不需要前端构建产物）
   - 分析器误判（如把 `scripts/` 误识别为前端目录）
4. **中文输出**：所有 reason / suggestion 字段用简体中文
5. **JSON 格式**：严格按 `spec.md` 输出，不要包在 ```json 围栏里，不要输出 JSON 以外的文字

## 准确性判定标准

- **high（高）**：分析器判定正确，证据充分，无异议
- **medium（中）**：分析器判定基本正确，但证据弱或有边界情况需说明
- **low（低）**：分析器判定有误或证据不足，需在 suggestion 说明应如何修正

## 可忽略判定标准

- **true**：该分析结果可忽略（如轻量项目不需要、产物对项目类型无意义、误判）
- **false**：该分析结果不能忽略，需要用户关注

## 边界情况

- 如果 stepType 是 phase 但项目 files < 20，大概率是轻量项目，阶段进度低可忽略 → canIgnore: true
- 如果 stepType 是 artifact 且该产物对当前 profile 无意义 → canIgnore: true
- 如果分析器把非目标文件误识别为产物存在 → accuracy: low, canIgnore: true
