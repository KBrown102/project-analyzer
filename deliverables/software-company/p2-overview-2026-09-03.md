## P2 方向 1：历史快照留存钩子（已完成）

**解决的问题**：产品经理指出"留存钩子为零，看一眼就用完工具"是最大风险。

**实现**：
- 每次分析成功后自动存摘要到 localStorage（20 条滚动删最旧，HIST_SEQ 自增防同毫秒撞 id）
- 顶部「历史」按钮（带 N/20 badge）→ 抽屉列表（时间/项目名/文件数/类型/模板/阶段完成度 + 回看/删除）→ 详情模态
- localStorage 不可用/配额满/序列化失败 → 静默降级不阻断主功能

**踩的真 bug**：`Date.now()` 同毫秒撞 id 导致误删——npm test 下才暴露（单独跑 logic 因跨毫秒偶然过）。用 `Date.now()+HIST_SEQ++` 修复。

## P2 方向 2：advice 数据化（暂缓）

**评估结论**：QA 说减 483 行（-21%），但 P1 已重构 score（149 行已数据化为 SCORE_REGISTRY）。剩下的 advice 群 483 行/112 条规则，数据化后真实减重约 **158 行**，主要价值是"加模板只改数据表"的预防性铺路。当前无加模板计划时边际价值低，风险中等（advice 输出须 byte-for-byte 不变）。

## P2 方向 3：JSON 导出（已完成）

**解决的问题**：用户可把分析结果导出为 JSON 存档/分享/二次加工。

**实现**：
- `exportJSONData(items)` 返回 {name,json,mode,count}（纯序列化，items 可选，测试可传参）
- `exportJSON()` 调 exportJSONData + Blob 下载
- 顶部「导出 JSON」按钮 + 绑定
- 单项目导出 data 对象；对比模式导出 {projects:[A,B],compare:true}
- 文件名 pa-项目名-时间戳.json，对比模式用 -vs- 连接

## 关键教训（本轮新增）

1. **闭包变量测试注入**：`exportJSONData()` 读闭包 A/B，测试无法直接设。改签名 `exportJSONData(items)`（items 可选）才让测试传参测 payload 构造，否则 payload 构造是盲区，变异验证改坏也抓不到。
2. **smoke 正则断言签名敏感**：改函数签名后 `/function exportJSONData\(\)/` 不匹配，要 `/function exportJSONData\(/` 宽松匹配。
3. **harness localStorage mock**：测存档逻辑必须给 vm 注入 localStorage（Map 实现），否则 HAS_LS 恒 false 全降级返回 null，存档逻辑测不到。
4. **Date.now() 精度坑**：同毫秒连续调用返回相同值，做 id 要加自增计数器。npm test（机器忙）比单独跑更容易暴露。
